# Knowledge Rules

Knowledge root:
`/media/oscar/Data/workspace/knowledge`

## Purpose

`knowledge/` contains curated, reusable information organized for retrieval and reuse.

Knowledge files are optimized for efficient retrieval and reuse:
- concise
- structured
- one concept per file when possible
- no unnecessary explanations

## Storage Roles

`inbox/`
Temporary incoming material waiting for processing.

Examples:
- downloaded PDFs
- web captures
- external documents

`documentation/`
Raw references and source material.

`knowledge/`
Curated, reusable information.

`knowledge/indexes/`
Generated indexes and navigation data.

## Knowledge File Structure

Knowledge files should contain:

- Clear title describing the subject.
- Concise description when useful.
- Structured content organized by topic.
- Relevant sources used to create or verify the information.
- Review date when information may become outdated.

Prefer:

- Official documentation as primary sources.
- Reliable references for technical information.
- Links to external sources when available.

Avoid:

- Unverified technical information.
- Vague source references.
- Mixing unrelated concepts in the same file.

## Rules

- Do not store raw documents in knowledge.
- Do not store temporary tasks in knowledge.
- Avoid duplicate information.
- Follow the classification rules defined in `knowledge_structure.md`.
- Do not create new top-level categories without approval.
- Keep Markdown files small to reduce context usage.
